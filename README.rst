Historical Data Compatibility Repair Resource v0.1.1
====================================================

Eight localized repair tasks from six Python projects, with immutable artifacts
generated by genuine historical releases. Each task asks for a general library
repair that preserves the declared old-data, current-behavior and restart
contract. There are 65 distinct historical files and 252 dependent observations,
not 252 independent bugs. This resource does not claim a new upgrade-testing
algorithm or stronger discrimination than authentic upstream regression tests.

Quick start (free verification)
------------------------------

Static integrity, saved-record and paper-number checks need Python 3.10+;
they do not require Docker or ARM64. All 65 historical files are released;
48 were withheld from the agent during repair only. To execute repair behavior,
use a native Linux ARM64 machine with a working local Docker installation. The tested runtime is CPython3.10.20 with NumPy1.26.4 and
pandas2.1.4. Native candidate binaries are ARM64. Other architectures have not
been qualified. From this directory::

    python3 compat.py integrity
    python3 compat.py list
    python3 compat.py bootstrap --pull
    python3 compat.py reproduce --controls base,fixed,reference

Recompute all published Gemma patch decisions, without generating model responses::

    python3 reproduce_main.py --records-only
    python3 reproduce_main.py --output results/main-check

The complete 32-patch replay executes 1008 observations and checks the same four
complete accepts. Process-dependent partial counts for broken dtype readers can
vary; the original measurements and fresh replay are both retained.

Reproduce the two valid policies and the incorrect nearby policy::

    python3 reproduce_multisolution.py --output results/multisolution-check

The expected admissible counts are 84/84,84/84,0/84; literal reference equality
gives 84/84,24/84,0/84. This is a constructed calibration on one lineage. The 60
different observation rows reuse five historical files in twelve processes;
they are not 60 bugs, a natural failure frequency, or additional Gemma attempts.
The comparator is literal fixed-reader equality, not authentic upstream tests.
The earlier v1 empty-column issue and separately frozen guarded v2 are included.

The first pull obtains an image by digest. The included, hash-checked wheelhouse
allows package installation without network access. Candidate checks use no
network or model API key. A previous Docker image cache may be reused; package
targets are freshly installed and each attempt has a retained receipt.

To inspect one task and verify its reference repair::

    python3 compat.py reproduce --task attrs_slot_state_1085 --controls reference

To evaluate a new patch::

    cp -a bundle/packages/attrs_slot_state_1085/base ./my-candidate
    # Edit only the source paths allowed for this task in tasks.json.
    python3 compat.py verify --task attrs_slot_state_1085 --candidate ./my-candidate

An ordinary unified diff or exact-text edit JSON is also accepted instead of a
full directory. See CLI_USAGE.txt. The verifier checks allowed paths and source
syntax on the host, and executes the candidate in a read-only, network-disabled
container with 1 CPU, 1GB memory, dropped capabilities and temporary workspace.
Historical files are copied before writable-map operations. Expected observations
are host-side frozen files: verification never regenerates them from a candidate.

The base control must expose the declared historical defect. Fixed controls are
complete upstream readers; reference controls are repairs confined to the allowed
files of the affected base. A full release upgrade is not a permitted solution
to an agent task. Exit0 means the requested checks passed; exit1 is a negative
evaluation, exit2 an invalid input/setup failure. Inspect execution receipts to
separate runtime problems from observed semantic failures.

Resource and result identities
------------------------------

* tasks.json states requests, producer/base/fixed versions and editable paths.
* bundle/ contains authentic reader/source copies, fixtures and worker code.
* oracle/ contains frozen observations with separately audited input invariants.
* reference_repairs/ contains authentic upstream-derived allowed-file repairs.
* provenance/ binds official source URLs, archive hashes and license copies.
* evidence/ contains main-plan identities, final patches, actual observations and
  recorded model conversations. Its export manifest declares author-path
  redactions and retains both original and exported hashes. Patch bytes are not
  redacted. Original study evidence remains archived by the authors.

Use the top-level integrity manifest as the identity of this distribution.
Installed bytecode and installer lock files have been omitted from source copies;
their exclusion is recorded rather than represented as unchanged package bytes.
Historical producer folders are explanatory source, not complete installations.
Frozen generated bytes are provided for exact benchmark replay. Fresh artifact
generation can vary with producer process ordering; it is a new sample.

The jsonpickle dtype task deliberately permits value/kind-preserving widening
only for declared historical numeric positions without explicit width suffixes.
Explicit legacy widths and newly written widths remain exact. A recorded267-byte
float32/float64 collision motivates this admissibility boundary. Twelve fresh
reader trials reuse six historical files; trials of public bytes remain public
bytes. SQL covers one MutableDict property; CSV covers text/object frames.

Model reruns (optional and paid)
-------------------------------

The released outcomes come from two pinned Gemma deployments under one frozen
bounded protocol. They differ in provider and precision as well as model size.
The first four task lineages were development-exposed; four were introduced for
the main run. No clean pretraining holdout or size-causal inference is claimed.

Preparation prints a plan and makes no API request::

    python3 model_runner.py --task attrs_slot_state_1085 --deployment 26b --replicates 1

To execute, set OPENROUTER_API_KEY in the process environment, then explicitly
opt in with a new output directory and a chosen maximum budget::

    python3 model_runner.py --execute --budget-usd 0.50 --task attrs_slot_state_1085 --deployment 26b --replicates 1 --output ./runs/my-new-study

No key is loaded from or written to this distribution. Requests use the pinned
provider with fallback disabled and explicit price limits. Missing/failed cost
receipts retain conservative reservations. A pre-existing run ledger cannot be
silently reset. Calls stop at the budget bound; an insufficient budget can leave
attempts incomplete, which is an execution outcome, not scientific repair failure.
The protocol allows24 exploration rounds, a120KB exploration-context stop,
24KB shown-tool truncation, marked context compaction and a reserved final report.
Full raw tool returns and actual request contexts are retained. Model reruns are
stochastic and do not replace the published measurements.

The published agent scaffold has known tool friction: whole-tree literal search
assumes UTF-8 even though some source files declare another Python encoding;
exact-text editing also requires an unambiguous literal match. Such errors are
retained in the measured conversations. The default runner preserves these
conditions rather than presenting an improved scaffold as the original study.
Free candidate verification and control reproduction do not use source search.

Interpretation and reuse
-----------------------

Passing finite checks establishes this contract's tested observations, not general
library correctness. Optional tests are graded separately. General-repair source
review remains necessary to reject fixture hardcoding or verifier manipulation.
This is an open research resource, not a secure hidden evaluation service: users
can inspect released private-to-agent data outside the tool interface.

Two tasks share joblib and two share jsonpickle. Artifacts, checks and model
conversations are dependent, and historical fixes may be memorized. All empirical
claims must use complete attempts and distinguish protocol, runtime, semantics
and source-policy acceptance. The separate12-attempt development comparison
observed the same2 accepts under genuine upstream tests and lifecycle checks;
there was no additional complete-patch rejection.

Manuscript source and numeric checks
-----------------------------------

The paper/ directory includes the supplied PDF, audited structured content,
BibTeX, text with versioned public figure links, and a portable renderer. Three vector
figures and one complete resource/control/result table accompany the manuscript.
The bibliography has fifteen research/model/upstream/tool-documentation sources;
figure software is acknowledged separately. Figure data, generation code and alt text are included; see
paper/FIGURES.rst. Check manuscript
counts against the result records without Docker or API access::

    python3 paper/verify_numbers.py

To regenerate document layout (optional; separate from evaluation dependencies)::

    python3 -m pip install -r paper/requirements-paper.txt
    python3 paper/render.py --output ./manuscript-rerender.pdf

This renderer uses standard Times fonts. The supplied PDF uses embedded Times
New Roman, so content is fixed but pagination/PDF bytes need not be identical.
